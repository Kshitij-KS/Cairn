    How to read this map

    Each circle is one note in the team's shared memory. Each line is a relation the note declares, which is the same path an AI agent follows when it looks something up.

    Levels decide who may change a note

      Why you see groups first

      A pane this size fits roughly sixty labelled things before the names start colliding, and that limit is about type, not about speed. So the map shows one depth at a time: the groups, then one group opened, then one note with its neighbours drawn in around it. Every group physically contains its notes, so going deeper is a move into a place rather than a jump to another screen.

      By area groups notes by where they live, which is the shape of what the team knows. By time groups them by month, which is the shape of what has been happening. Both are the same corpus.

      What the marks mean

      • Circle size is how much a thing holds: facts for a note, notes for a group.
      • The bar under a group is its mix of levels.
      • A heavier line is a dependency: depends_on, implements, part_of, supersedes. These are the paths a planning change travels along.
      • A lighter line is relates_to, meaning see also. These deliberately do not carry a change outward.
      • An amber ring means a planning change landed upstream and nobody has re-read the note yet.
      • A note that changed in the last week breathes faintly.
      • Light running along a dependency shows which way a change travels: from the note that is relied on to the notes that rely on it, the path a planning change cascades along.

      Getting around

      • Select a group to open it, a note to bring it close.
      • Escape or Backspace backs out one level. So does clicking empty space.
      • / jumps to search, which reaches any note at any depth.
      • Every view has its own address, so a link you paste opens exactly what you were looking at.
